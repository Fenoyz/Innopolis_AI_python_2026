## 1. Четыре слоя чистого линейного скрипта (Data Pipeline)

Профессиональные разработчики никогда не перемешивают чтение с клавиатуры, сложные формулы и `print()` в одну кашу. Любая расчетная программа строится как **конвейер обработки данных (data pipeline)** из $4$ четких блоков:

```text
[ 1. Сбор сырья ]  --->  input() (получаем необработанные строки str)
        |
        v
[ 2. Очистка и типы ] -> .replace(",", "."), int(), float(), защита от 0
        |
        v
[ 3. Ядро расчетов ]  -> //, %, **, min(), max(), булевы флаги
        |
        v
[ 4. Чистый отчет ]  --> f-строки с :.2f и :02d, табуляция \t и рамки
```

> [!IMPORTANT]
> **Золотое правило читаемости:** Внутри финального блока `print()` не должно быть громоздких трехэтажных формул — выводи туда уже посчитанные переменные с понятными именами в стиле `snake_case`!

## 2. Финальный чек-лист перед контрольной работой по Теме 2

Проверь себя по этим $6$ пунктам перед стартом Урока 16:

| Ловушка | Как работает в Python на самом деле |
| :--- | :--- |
| **Что возвращает `input()`?** | Всегда строку `str`! Без `int()` или `float()` оператор `*` продублирует текст (`"5" * 2` даст `"55"`). |
| **Разница между `/` и `//`** | `8 / 2` всегда возвращает `float` (`4.0`), а `15 // 4` возвращает целую часть (`3`). |
| **Зачем нужен `%` (остаток)?** | Возвращает хвост после деления нацело: `125 // 60` дает `2` минуты, а `125 % 60` дает `5` секунд. |
| **Чем `int(4.99)` отличается от `round(4.99)`?** | `int(4.99)` отсекает дробную часть до `4`, а `round(4.99)` округляет до `5`. |
| **Подвох `int("2.5")`** | Вызывает ошибку `ValueError`! Дробную строку сначала переводят через `float("2.5")`. |
| **Подвох `bool("False")` и `bool("0")`** | Оба выражения равны `True` (в арифметике это $1$), так как строки не пустые! `False` дает только `bool("")` и `bool(0)`. |

## 📚 Словарь разработчика

* **Конвейер данных (data pipeline)** — последовательная архитектура программы, где выход одного этапа обработки служит входом для следующего.
* **Отладка (debugging)** — процесс поиска, диагностики и исправления синтаксических и логических ошибок (багов) в коде.
* **Исключение (exception)** — сигнал интерпретатора об аварийной ситуации во время работы программы (`TypeError`, `ValueError`, `ZeroDivisionError`).
